# User Story: Dark Mode on Settings Page

## User Persona

**Name:** Accessibility-Conscious Professional

**Description:** Maya is a knowledge worker who spends long hours in front of screens for research, writing, and collaboration. She prefers a comfortable viewing experience in low-light environments and wants to control how the application looks without digging through advanced technical options. Her primary goal is to reduce eye strain during evening work while keeping settings easy to find and change.

## User Story

- **As a** Accessibility-Conscious Professional
- **I want to** switch the settings page to a dark appearance
- **so that** I can work comfortably in dim lighting and reduce eye strain without leaving the settings area

## Acceptance Criteria

- WHEN I open the settings page THEN I SHALL see a clear option to choose between light and dark appearance
- WHEN I select dark appearance THEN I SHALL see the settings page update to a dark color scheme immediately
- WHEN I return to the settings page after choosing dark appearance THEN I SHALL still see dark appearance applied
- WHEN I switch back to light appearance THEN I SHALL see the settings page return to a light color scheme
- WHEN I view text, labels, and controls in dark appearance THEN I SHALL be able to read all content clearly without difficulty
- IF I change appearance on the settings page THEN I SHALL see my choice reflected consistently across all sections of that page

## Success Metrics

**Primary Metric:** A tester can open the settings page, switch to dark appearance, leave and return, and confirm dark appearance is still active (pass/fail).

**Secondary Metrics:**

- All text and controls remain readable in dark appearance (pass/fail)
- A tester can switch back to light appearance and confirm the page returns to a light color scheme (pass/fail)

**Verification Requirements:** Each metric can be validated through manual user-facing tests with simple pass/fail results.
